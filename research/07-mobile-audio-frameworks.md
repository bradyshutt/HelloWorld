# Mobile Audio Recording Frameworks

## Summary

For a voice journal app, the recording layer must handle microphone permissions, lock-screen/background continuation, and reliable file management on both iOS and Android. Native APIs (AVFoundation/AVAudioEngine on iOS, MediaRecorder/AudioRecord on Android) offer maximum control but require platform-specific work, including a microphone-typed foreground service on Android 14+. Cross-platform options have matured in 2025: Expo's new `expo-audio` (with `enableBackgroundRecording`), Flutter's `record` package, and Capacitor plugins all expose decent recording APIs, while Kotlin Multiplatform libraries (Kodio, kmp-record) and Tauri's `tauri-plugin-audio-recorder` are viable but less battle-tested. For a journaling app, Expo (managed) or Flutter `record` are the fastest paths to a polished MVP; native or KMP is preferable if real-time DSP/transcription pipelines are central.

## Native iOS

iOS exposes audio capture through **AVFoundation**, with `AVAudioRecorder` for simple file-based recording and `AVAudioEngine` when you need a real-time graph (effects, streaming, live transcription) ([Apple AVAudioEngine forum](https://developer.apple.com/forums/tags/avaudioengine), [AVAudioEngine guide](https://arvindhsukumar.medium.com/using-avaudioengine-to-record-compress-and-stream-audio-on-ios-48dfee09fde4)). You configure an `AVAudioSession` with the `.record` (or `.playAndRecord`) category before capture. Background recording requires enabling the **Audio, AirPlay, and Picture-in-Picture** background mode in Signing & Capabilities; with that set, recording continues seamlessly when the screen locks, with only the orange status-bar indicator shown ([Apple NSMicrophoneUsageDescription](https://developer.apple.com/documentation/BundleResources/Information-Property-List/NSMicrophoneUsageDescription)). Permissions are gated by `NSMicrophoneUsageDescription` in `Info.plist` plus `requestRecordPermission` at runtime ([Apple docs](https://developer.apple.com/documentation/avfaudio/avaudiosession/requestrecordpermission(_:))). Apps must handle interruptions (calls, Siri) via `AVAudioSession` interruption notifications. Files typically go to the app's Documents directory; iCloud or Files-app exposure requires extra Info.plist keys.

## Native Android

Android offers **MediaRecorder** (high-level, file-based, recommended for journaling) and **AudioRecord** (raw PCM for live processing/streaming) ([Android MediaRecorder docs](https://developer.android.com/media/platform/mediarecorder)). Since Android 9 (API 28), microphone access is forbidden from pure background processes — you must run a foreground service. Starting **Android 14 (API 34)**, that service must declare `android:foregroundServiceType="microphone"`, the app must hold `RECORD_AUDIO` plus the new `FOREGROUND_SERVICE_MICROPHONE` permission, and call `startForeground` with `FOREGROUND_SERVICE_TYPE_MICROPHONE` — otherwise the system throws `SecurityException` ([Android FGS types](https://developer.android.com/develop/background-work/services/fgs/service-types), [Android 14 FGS changes](https://developer.android.com/about/versions/14/changes/fgs-types-required)). A persistent notification is mandatory and visible while recording. On Android 13+ runtime permission requests for `RECORD_AUDIO` and `POST_NOTIFICATIONS` are required. Files commonly land in app-private storage (`getFilesDir()`); use `MediaStore` if you want them user-visible.

## Cross-Platform Options

- **Expo / React Native**: `expo-audio` is the supported successor to `expo-av` (deprecated, removed in SDK 55). The config plugin's `enableBackgroundRecording: true` automatically wires the iOS background mode and Android foreground-service permissions and notification ([Expo Audio docs](https://docs.expo.dev/versions/latest/sdk/audio/), [DEV: background audio in Expo](https://dev.to/josie/how-to-add-background-audio-to-expo-apps-3fgc)). Requires a development build (not Expo Go). For bare RN, `react-native-audio-recorder-player` remains active ([npm](https://www.npmjs.com/package/react-native-audio-recorder-player)).
- **Flutter**: The `record` package is the most actively maintained option, with multi-codec output, streams, and explicit background support ([pub.dev/record](https://pub.dev/packages/record)). `flutter_sound` is heavier but offers PCM streams useful for live transcription ([pub.dev/flutter_sound](https://pub.dev/packages/flutter_sound)).
- **Capacitor / Ionic**: `@capgo/capacitor-audio-recorder` and Capawesome's audio-recorder plugin both support iOS/Android with start/pause/resume/stop and background recording when the iOS Audio background mode is enabled ([Capgo plugin](https://github.com/Cap-go/capacitor-audio-recorder), [Capawesome](https://capawesome.io/plugins/audio-recorder/)). `capacitor-voice-recorder` is a simpler legacy option.
- **Kotlin Multiplatform**: `Kodio` offers coroutines-based recording, playback, transcription, live waveforms, and built-in permission handling across Android/iOS/desktop/web ([Kodio](https://klibs.io/project/dosier/kodio)). `kmp-record` and `kmp-audio-recorder-player` are lighter alternatives ([kmp-record](https://github.com/theolm/kmp-record)).
- **Tauri Mobile**: `tauri-plugin-audio-recorder` (Tauri 2.x) supports iOS/Android with M4A/AAC output and quality presets, but the ecosystem is young and background recording on Android still needs manual manifest plumbing ([tauri-plugin-audio-recorder](https://github.com/brenogonzaga/tauri-plugin-audio-recorder)).

## Recommendations

For a voice-journal MVP that needs lock-screen recording, AI playback, and rapid iteration: start with **Expo (`expo-audio` + `enableBackgroundRecording`)** or **Flutter `record`** — both abstract the iOS background-mode + Android foreground-service complexity that otherwise dominates native development. Choose **Kotlin Multiplatform with Kodio** if you also want a desktop client and prefer Kotlin; choose **native AVAudioEngine + AudioRecord** only if real-time on-device processing (e.g., streaming to Whisper, voice-activity detection, custom codecs) is central. Avoid Tauri Mobile for v1 unless the team is already Rust-heavy. Regardless of stack, plan for: (1) chunked file writing with rotating segments to avoid losing long sessions, (2) graceful interruption recovery (calls, Siri, headphone unplug), (3) clear UI affordances around the orange iOS indicator and the un-dismissable Android recording notification, and (4) explicit, journaling-specific permission rationale strings.
